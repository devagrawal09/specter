Two deliberately separate surfaces

Language-neutral protocol
  • Runtime → collector specification publications
  • Runtime → collector observation batches
  • Independent acknowledgements, versioned schemas, and shared fixtures
Collector-owned API
  • Specification maps with correlated telemetry
  • CLI snapshot, watch, and trace
  • Catalog, read, stream, and explicit pruning routes

The dashboard and CLI are collector clients, not protocol clients.

What stays native

Runtime implementation

Commands, Queries, Reactions, handlers, schemas, and plugins.

Application transport

Each project chooses and owns HTTP, SSE, WebSocket, queues, or in-process calls.

Persistence

Database schemas, locking, projections, and outboxes remain runtime-specific.

Why this is simpler

  • No generic remote Command or Query server in TypeScript or Go.
  • No capability negotiation for a single-purpose telemetry contract.
  • No TypeScript core dependency in the protocol types package.
  • No ambiguity about whether the dashboard can mutate an observed app.
  • Independent conformance targets for portable specifications and safe, retryable observations.
