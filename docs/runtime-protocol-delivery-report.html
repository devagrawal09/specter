01 / Architecture

A protocol between runtimes and tools—not between domain models.

The contract standardizes observable outcomes and messages. Slices, handlers, schemas, stores, and plugins remain language-native. Event order remains local to an Event Log.

Transport is an adapter boundary. The protocol includes an HTTP/JSON and SSE reference binding, but the behavioral contract is not tied to HTTP, SQLite, Postgres, or a shared application manifest.

02 / What shipped

A complete vertical slice, from specification to live debugging.

The implementation covers the neutral specification, two conforming runtimes, production-safe telemetry, a persistent collector, developer tools, reference applications, and CI.

1

Normative protocol area

Behavioral documentation, JSON Schemas, golden fixtures, and conformance vectors define versioning, capabilities, ordering, idempotency, cancellation, coalescing, causality, and public errors.

2

TypeScript protocol package

@specter-ts/protocol provides public types, validation, capability negotiation, clients, servers, HTTP/SSE bindings, and the adapter to the TypeScript runtime.

3

Causal runtime observations

TypeScript core operations carry operation and correlation IDs, parent relationships, triggering Event ranges, and Reaction identities without making core depend on networking.

4

Independent Go runtime

The standard-library-only Go module implements Commands, Queries, subscriptions, Events, projections, immediate Reactions, structured errors, scenarios, HTTP/SSE, and telemetry.

5

Specter-native collector

Observation batches enter through a Command, become explicit operational Events, and feed overview, activity, and trace Queries. The collector avoids observing itself recursively.

6

Durable developer tooling

The read-only browser dashboard and specter-observe CLI support source filters, activity streams, lag and failure signals, snapshots, NDJSON watch, and causal traces.

7

Best-effort telemetry producer

Producers batch up to 100 records, queue up to 10,000, never await network I/O on the application path, retry while alive, and report recovered loss after dropping oldest observations.

8

Reference workflow and cleanup

TypeScript Todo and Go Todo appear together in the collector. CI exercises both directions. Legacy embedded recorder and development-panel APIs were removed; starters remain unchanged.

04 / Product and framework impact

Specter becomes an ecosystem boundary, not only a TypeScript library.

The protocol makes runtime behavior portable and observable while preserving the framework’s strongest property: applications stay explicit, local, and idiomatic.

Strategic shift

Language growth no longer requires duplicating the developer experience.

A new runtime can conform to the shared behavioral fixtures and immediately participate in the same dashboard, CLI, traces, and transport ecosystem. Observability tooling is built once and reused across every language.

  • Supports polyglot teams without fragmenting operations.
  • Creates a testable definition of what “Specter-compatible” means.
  • Allows clients and servers from different runtimes to interoperate.
Product

One debugging surface

Teams see Commands, Queries, Events, projections, Reactions, retries, dead letters, and failures across applications in one causal view.

Framework

Sharper architecture

Core execution remains network-independent. Protocol validation, transport, telemetry, persistence, and UI now sit at explicit adapter boundaries.

Developer experience

Faster root-cause analysis

Operation IDs, correlations, parents, triggering Events, and retry-stable Reaction identities reconstruct work across asynchronous boundaries.

Safety

Operational isolation by default

Telemetry is metadata-only, bounded, non-blocking, redacted, and best-effort. Collector failures cannot change application execution.

Adoption

A credible runtime certification path

Normative schemas and golden behavior fixtures provide a concrete route for future Rust, Python, Java, or .NET implementations.

05 / Deliberate boundaries

What is standardized—and what stays native.

The boundary is intentionally behavioral. This avoids turning the protocol into a lowest-common-denominator application language.

Protocol-owned

  • Envelope, IDs, timestamps, versions, and capabilities
  • Command commit, duplicate, rejection, and expected-version semantics
  • Query, subscription, cancellation, and coalescing behavior
  • Event references, ordering scope, and projection cursors
  • Reaction tickets, retry-stable identities, and public errors
  • Runtime observations, causality, batching, acknowledgement, and dedup

Runtime and application-owned

  • Slice specifications and domain schemas
  • Command, Query, and Reaction handlers
  • Scenarios and language-native testing APIs
  • SQLite and Postgres schemas or locking implementations
  • Persistent-store interoperability across languages
  • Plugins and application wiring
06 / Potential next steps

Harden the contract, deepen the tools, then expand the ecosystem.

The best next investments are sequenced to protect v1 semantics before broadening runtime and production scope.

Now · Harden v1

Turn the reference into a release-quality contract.

  1. Add browser automation for filters, live reconnect, and causal traces.
  2. Expand malformed-message and long-running cancellation fixtures.
  3. Publish a conformance runner with machine-readable certification output.
  4. Benchmark telemetry overhead, backpressure, and collector ingestion.
  5. Resolve the unrelated root-suite OpenAPI fixture dependency.
Next · Productionize

Make the collector useful beyond trusted local teams.

  1. Add authentication, tenant isolation, and source registration.
  2. Add retention policies and cross-segment historical Queries.
  3. Support secure transport, compression, and collector health metrics.
  4. Add dashboard saved views, comparison windows, and shareable trace links.
  5. Define collector upgrade and protocol migration procedures.
Later · Grow ecosystem

Prove the protocol across more languages and transports.

  1. Add a third runtime to expose hidden TypeScript/Go assumptions.
  2. Implement Go durable Reaction outbox and database adapters.
  3. Add WebSocket, message-bus, or local IPC binding experiments.
  4. Publish runtime-author guidance and compatibility badges.
  5. Explore OpenTelemetry export without weakening Specter causality.
07 / Design principles preserved

The protocol extends Specter without diluting it.

Explicit over magical Operational behavior is represented by named messages, Events, and Queries.
Behavior over storage Conformance describes outcomes, not tables, locks, or persistence internals.
Language-native applications No portable application manifest replaces idiomatic handlers and schemas.
Failure isolation Telemetry cannot delay, reject, or alter application work.
