Current boundary

Specifications and telemetry, together.

0.4 readiness means proving that portable behavior and language-neutral telemetry correlate exactly while application APIs remain project-owned.

Scope checks

Two ingestion lanes

POST /specter/v1/observations and POST /specter/v1/specifications accept independently acknowledged messages.

No operational wire API

No capability, Command, Query, subscription, or Reaction-ticket message family remains.

Collector APIs are separate

The browser and CLI use collector-owned catalog, overview, activity, trace, stream, and pruning routes.

Native application APIs

TypeScript and Go examples execute runtime envelopes through project-owned transports.

Correctness evidence required

  • Normative JSON Schemas cover observation batches, specification publications, and their acknowledgements.
  • Shared fixtures cover valid metadata and specifications, malformed input, version mismatch, causality, unknown optional fields, and Event ordering.
  • Retry tests prove an in-flight batch is immutable and deduplication uses observation identity.
  • Digest tests prove telemetry resolves to the exact immutable specification published by a runtime.
  • Queue overflow, collector outage, restart persistence, rotation, and metadata redaction remain covered.
  • TypeScript and Go producers both appear in the shared collector.
  • Repository TypeScript and Go baselines pass before the PR is marked ready.

Compatibility

Protocol v1 keeps generic operational routes out of the collector while adding specification publication as an independent ingestion lane. Applications expose their own operational APIs; the collector owns immutable specification catalogs, metadata-only telemetry, correlation, and visualization.
